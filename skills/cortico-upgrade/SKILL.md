# Cortico 可靠升级

交付一套可选用的新版本，同时保留可恢复的旧环境。只问影响时只分析；用户授权执行后继续完成迁移、验证和交付，不把此 skill 当成额外授权或每步确认流程。

## 先确定真正的运行环境

- 找到当前 corti-soul 仓库，读取目标仓库现行 AGENTS.md；改变工具、提示词或上下文前按其要求阅读 PHILOSOPHY.md。
- 优先读取 `runtime-selection.json`、`launcher/runtime_paths.py` 与 `tools/cortico-runtime.py status`，核实实际进程、部署、package.json 和 Git HEAD。不能假设同级 `cortico-qq` 仍是当前版本。
- 分别盘点自有仓库、当前框架树的 tracked 修改、未跟踪模块、安装后的第三方扩展补丁、私有资源和构建产物。Git HEAD、git diff、若干 `.orig` 文件都不等于完整恢复点。
- 查官方迁移说明及固定标签之间的差异，锁定提交；不直接追浮动 main，也不把本次公告之外的升级一并带入。
- 简短告诉用户主要影响与范围。项目已决定废弃饥荒扩展；除非用户重新要求，不安装、不启用、不迁移它，旧数据保留。

## 在独立目录迁移

保留当前运行树，候选放在新的 `runtimes/<目标版本或唯一名称>`；探索、冲突试验放 scratch。读 [references/project-map.md](references/project-map.md) 查现有入口和历史迁移陷阱。

迁移的单位是当前部署的实际定制差异，不是旧补丁脚本列表：

1. 保存现有源码快照，包含新增源文件和扩展包内实际修改；排除凭据、聊天、运行日志与人格数据。需要合并时，在隔离分支执行，并追踪上游重命名。
2. 分别适配启动器/API、WebUI 面板、MC 行为模块、人格上下文与交接、模型守卫、独立观看服务。检查所有入口是否选择同一运行目录。
3. 对连接生命周期、重连预算、暂停/手动恢复等语义冲突逐块处理。禁止用全选旧版/新版或全局字符串替换掩盖冲突。扩展兼容层的覆盖范围须读源码确认。
4. 根据候选自己的锁文件安装依赖。Windows pnpm junction 可能指向安装时的绝对目录；不要搬走已安装目录后假设链接仍有效。长期目录独立安装，扩展本地补丁要在其中保留，不能通过共享链接写回旧版。
5. 将适配结果做成注明支持版本、全量预检、失败不写入且可重复检查的自有补丁；在干净官方副本验证安装和重复安装。下一版不能盲用上一版补丁。

保持项目边界：World 保存外部事实，不直接写人格 Memory；自有定制避免侵入 Core 和通用 WebUI。保留家/床/设施、建筑授权和保护、夜间休息、门、设施复用、地表寻路、卡死证据、用量时间线，以及 QQ/MC 共用人格的既有行为；升级不顺便重设玩法或免费池策略。

## 用有限验证取得证据

- 修复阶段先跑相关测试、服务端与浏览器类型检查；完成后按当前 AGENTS.md 跑最终完整回归。只有新失败或后续改动才追加必要验证，避免反复轮流大范围验证和长时间盯日志。
- 分类测试失败：实际回归、旧断言与既有定制不符、环境限制。先读实现和用户已确认的行为，再修测试；不能为过测试撤掉保护、允许挖路/随意 TP 或丢弃最后发言回执。
- 假世界回放关键流程；只加载扩展定义验证兼容性。测试不得连接真实模型、主动发 QQ 或启动真实 bot；启动器 EXE 会自动拉起服务，不能随手运行来验证打包。
- 构建遵守仓库要求：本项目 build:web 前确认本机没有真实 bot 进程，端口关闭还不足以证明进程已退出。候选路径独立也不能忽略此要求。
- 区分源码/测试通过、构建通过、目录切换通过和用户真实 QQ/MC/手机验收；不把前几项写成最后一项。

## 一致备份、切换与回退

- 切换前正常停止写入者和相关启动器，防止旧进程持有原目录或守卫自动拉回旧环境。已有授权足够时直接执行必要动作并告知；缺权限或无法确定写入者时停止依赖该条件的操作。
- 建立本次独有的备份目录，保留旧程序、依赖、构建、部署配置/.env、workspace/记忆 Git 历史、session/core 状态、MC 账本和所需资源，生成校验清单。检查 symlink/junction，避免跨目录复制或遗漏。秘密只在本机受限位置保存，不入 Git。
- 若切换会改变游戏版本、操作服务端或需要恢复游戏进度，正常保存关闭后单独备份服务器存档与玩家数据；仅回退 Cortico 不会回退 MC 世界。
- 校验候选及备份后再原子更新选择文件；新旧版本不能同时写同一部署或同时连接同一真实账号。启动器、守卫、脚本、观看服务和桌面快捷方式要一致，快捷方式先备份再修改。
- 在停止状态验证新版→旧版→新版的选择路径，最终选用户要求的版本。实际启动与验收按任务授权和仓库规则执行，不为冒烟测试启动真实 bot。
- 提供简单回退入口：退出启动器，选回旧目录，再打开兼容启动器。新旧部署之后的记忆各自积累，不能自动覆盖或声称自动合并；覆盖恢复前说明会损失哪些新数据并保留新数据副本。

## 交付

核对当前自有版本后按用户规则更新：A 框架重构，B 功能更新，C Bug 修复；提升 B 时 C 归零。同步 VERSION、CHANGELOG、品牌 JSON、Windows FileVersion/ProductVersion 及独立构建目录。纯分析或文档工作不提升应用版本。

按已有授权提交/推送相关自有代码；明确路径暂存，排除其他会话改动、配置、凭据、运行树、备份和第三方二进制。验证远端提交。说明当前选用版本、原入口是否已更新、备份/回退入口、测试结果和待用户验收项；保持答复简短。
