# QQ 与 Minecraft 共用当前主模型（2.10.2）

规则：Cortico 的 `activeProvider` 是本部署模型选择的唯一来源。Minecraft/普通对话本来走 Core；QQ 辅助生成每次发出前读取同一部署的活动渠道，并同时取得地址、模型名称、密钥引用，不再把三个字段分开同步。辅助子任务仍有各自输入和请求，不等于共享一份完整对话上下文，也不等于只花一笔 token；人格连续性仍由现有 Persona/Memory 维持。

覆盖：QQ 主动消息、情绪感知、QQ空间生成/评论和主动/被动视觉。没有开启的功能保持关闭。QQ 发送、图片下载、游戏执行、TTS 服务不是文本模型路由，不改其连接方式。

## 为什么出现 18899

修复前本机 Dots/MiMo 的 provider 配置及视觉配置仍有 18899。这是配置中的遗留值，不是本轮新增监听器；仅凭现有材料不能认定由哪次操作首次写入。插件当前 `forward.port=18900`，列表只读请求确认原鉴权有效且含原有两个模型；另一个渠道仍是 8326。端口表示网关入口，并不能单凭端口判定具体模型或人格。

2.10.1 修通了当时主入口和部分辅助调用，但自动守护会恢复其他免费渠道，仍可能留下主模型与辅助调用分叉。旧守护只同步模型名、不带地址与鉴权，还要求已删除的 gaming 配置项；2.10.2 改为请求时解析活动渠道，并停止这套旧写入。

## 安装、限制与验证

先运行 `node patches/patch-qq-dialogue.mjs --apply`，再运行 `node patches/patch-qq-active-route.mjs --apply`。两者均支持 `--check`，版本限 QQ 0.1.17，锚点不匹配就停止；升级扩展后要重新适配。安装后正常重启 Cortico 和免费池守护，不能只关闭再打开启动器窗口来假定 bot 已重启。

统一路由适配当前的 `openai-responses-compat` 网关，辅助任务使用兼容的 chat/completions 协议。未适配的 provider 类型、坏配置、无鉴权不使用旧地址兜底。视觉依据主渠道声明的 `multimodal` 能力；不支持时暂停识图，不另选视觉模型。声明可用不等于经过真实图像生成验收。

自动或手动切换后，新辅助请求读取新渠道。已经发出的旧请求可能仍在网络中并消耗额度；若完成时选择已变化，其结果被丢弃。代码不会追溯取消 Core 已发请求，也不声称切换过程是全局原子事务。测试使用两个模拟部署渠道及拦截 fetch，覆盖地址/模型/密钥一起切换、旧结果丢弃、坏配置不请求、视觉跟随和无视觉不降级；不请求真实模型，不启动真实 bot。

交付检查：统一路由及实际扩展模拟调用 4 项、之前的收发模拟调用 3 项、手动模式 1 项及旧修复脚本 2 项均通过。重复安装的四个目标文件哈希一致；与对话补丁交替安装后预检仍通过。启动器独立构建 2.10.2，PE 版本与页面哈希已核验，桌面入口已备份并更新。真实 bot 和守护没有重启，运行验收待用户正常启动。

安装前的文件保存为扩展源码旁 `.active-route.orig`。回退时停止 Cortico，按当前 QQ 版本恢复 world.ts、vision.ts、config.ts 的相应备份；它保留了之前的对话补丁。不要把备份强盖未来扩展版本。旧启动器和本机渠道修复前配置仍保留。自有脚本、辅助模块和测试入库，运行配置与密钥排除入库。
