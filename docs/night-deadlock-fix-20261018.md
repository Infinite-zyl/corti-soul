# 夜间死锁修复

`patches/patch-minecraft-night-refusal.mjs` 的说明。2026-10-18 依据 run `r-20261018-004841-dc3a` 落地。

## 结论

两处判据与措辞的修改，不新增配置、不改数据结构：

| 改动 | 位置 | 作用 |
|---|---|---|
| 回执带上服务端拒绝原因 | `world.ts`、`skill-context.ts`、`skills-interact.ts` | 床被拒时回念动作栏原文，她才知道是怪的问题 |
| 夜间放行自保动作 | `executor.ts`（受理闸 + pump 两处） | `flee`/`attack`/`surface`/`eat` 不再被夜间闸门拒收 |

## 依据

76 分钟 run 实测，四个夜间窗口（`00:56:39–01:06:39`、`01:16:38–01:26:39`、
`01:36:39–01:46:39`、`01:56:39–01:57:48`，合计 31 分钟）：

| 指标 | 夜间 | 白天 |
|---|---|---|
| `mc_do` 次数 | **62** | 77 |
| 被拒 / 被合并 | **62（100%）** | **0（0%）** |
| 输入 token | 7.9 M（占全部 33%） | 16.0 M |

一个完整夜间窗口（01:16:38–01:26:39）的工具调用分布：
`mc_do ×18`（全被拒）、`end_turn ×12`、`qq_send ×6`、`mc_queue ×2`、`mc_bag ×1`。

她反复尝试 `goto` 回家 → 被拒、`use` 床 → 被合并、`find skeleton` → 被拒、
`attack zombie` → 被拒、`flee` → 被拒，中间穿插 6 次 QQ 说话
（「骷髅在东南边，离我大概 5 格」「知道，等天亮。你先去忙，我守着床」）。
**她知道自己被卡住，会汇报，但拿不到任何能执行的工具。**

## 根因

1. **回执只传现象不传原因。** 她收到的是「小麦种子右键了 (573,120,0) 的黄色床,
   没躺下(现在 dayTime 13264)」，而 `You may not rest now; there are monsters nearby`
   是另一条独立的 `minecraft.chat` 事件，两条之间没有关联。她读不出该去清怪还是换床。
2. **夜间闸门连自保动作一起拒。** `executor.ts` 的受理闸只放行 `nightRest` 单，
   `attack`/`flee`/`find` 全被归为普通工作——连"打掉门口的僵尸再睡"这条路都堵死。
3. **受理与执行两处判据不一致。** 即使受理闸放行，`pump()` 在夜间也只挑 `nightRest` 任务，
   放行的单会静默卡在队列里永远不执行。这是本次发现并一并修掉的隐性问题。

## 实现要点

- 新增 `REFUSAL_PATTERN`（`world.ts`）只认否定措辞，避免把「游戏已保存」这类播报
  当成拒绝原因；`REFUSAL_NOTE_MS = 5_000` 限定"这一步的原因"的时间窗。
- `SELF_PRESERVATION_SKILLS`（`executor.ts`）只认确切技能名，不按关键词猜：
  放过一个普通采集单会打乱夜间规则。
- 受理闸与 `pump()` 用**同一个** `isSelfPreservation` 判据，两处不会再分叉。
- 自保单仍受原有保护：队列顺序、抢占、夜间规则都不变，只是不再被无条件拒收。

## 回滚

    node patches/patch-minecraft-night-refusal.mjs --revert

脚本默认只预检；`--apply` 才写盘并留 `<文件>.night-refusal.orig`。
往返已验证：14 处 → 全部还原 → 12 处重新写入 → 幂等。

补丁脚本的锚点一律写成行数组用 `\n` 连接，不用模板字符串——
这些片段本身含反引号与 `${}`，在模板里会被插值，写出来的字面量与文件对不上。
