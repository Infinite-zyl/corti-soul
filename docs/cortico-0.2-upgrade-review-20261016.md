## 日常启动与回退

使用 `launcher/releases/2.10.0/corti-soul启动器/corti-soul启动器.exe`。启动器、守卫、PowerShell 启动脚本和观看服务共用 `runtime-selection.json`，文件不入 Git。

回退：先退出启动器，再运行根目录 `切回旧版Cortico.cmd`，然后仍用 2.10.0 启动器启动。恢复新版用 `使用新版Cortico.cmd`。脚本只切换目录，不覆盖任何记忆和存档；新旧部署的后续聊天和记忆各自在自己的目录积累，回退不会自动合并。

MC 服务端版本与存档本轮未修改，也未关闭游戏服务器；回退框架不等于回退游戏中的建筑和物品进度。

新版重装补丁使用 `patches/apply-cortico-0.2.mjs --root=<独立0.2.1目录> --check`，确认后 `--apply`。完整补丁在干净官方版本上已验证安装与重复安装；旧的分项补丁仍留作 0.1.x 维护，不在新版上逐个重跑。源码补丁与部署快照分开处理，补丁不包含配置、凭据、运行日志或记忆。

## 升级步骤与停止条件

1. **只读盘点**：固定目标标签/提交，保存两仓库状态、HEAD、锁文件、Node/pnpm 版本、EXE 版本、补丁安装顺序、配置文件位置和 SHA-256 清单。查明新增/未提交模块的来源；未知改动不能丢弃。
2. **准备隔离候选**：在独立目录放置目标版本，按锁文件安装依赖。旧运行目录保持原样；不上来就 git pull/reset/clean。按依赖顺序迁移住宅、保护/夜间、账本、自主行为、门、地表寻路、起点恢复、用量/时间线、上下文/QQ 补丁。锚点不匹配即停止适配该项，不能强行替换。具体顺序仍需依据各脚本读写关系核对。
3. **离线验证**：运行相关测试与类型检查，检查新契约 describe/check:extension；核对所有旧接口引用的用途，不能把 Python console 变量等无关名称全局替换。测试不得使用真实模型、QQ 收发或启动真实 bot。现有约束下，build:web 前也要确认本机 bot 已停止，不能在活跃运行时构建。
4. **切换窗口与一致备份**：用户暂停活动后正常停止写入配置、记忆、游戏状态的相关进程。分别备份完整 cortico-qq 运行目录（含 .git、未跟踪文件、deployments/mybot 的 .env/config/deployment、workspace、data、扩展注册和构建产物）、corti-soul 自有代码/配置与可用 EXE、观看 .runtime 配置。保留依赖或离线恢复条件。Minecraft 若在切换中运行/会被操作，正常保存关闭后备份整个 server 存档、玩家数据和服务端配置。密码和 Key 的备份仅在本机受限目录保存，不能进入 Git。
5. **验证备份**：检查清单、哈希、容量与抽样恢复。建立备份目录的明确绝对路径；不足空间或无法恢复即不切换。复制期间有写入的备份不能称为一致快照。
6. **正式切换**：保留旧目录，将候选部署接到启动器预期路径，或同时修正启动器/守卫/观看脚本路径。候选与旧版不能同时连接真实 QQ、同一 bot 账号或写同一部署目录。安装新构建和配置后，只启动一套。
7. **短验收**：WebUI、模型手动/自动模式、QQ 收发连续性、MC 账本/床/门/保护/夜间/寻路、用量时间线、三类游戏进程按钮、手机观看及手机关闭依次检查。先确认工具结果与游戏回执，再让用户实际玩。出现启动失败、档案丢失、保护失效、重复 QQ、关键按钮失效即停止放量。
8. **交付**：通过后按用户版本规则更新自有功能版本、变更日志和构建元数据；只提交推送自有相关代码。升级分析阶段不提升版本，不把运行数据或凭据提交到 Git。

## 回滚

- 先停新版及其自动重启来源，保存新版失败日志与数据副本，防止覆盖有用证据。
- **仅代码/界面回滚**：确认未发生不兼容数据写入时，恢复旧运行目录、旧依赖/构建、旧启动器和配套配置，保持原部署路径；不能只回退 Git 提交。
- **完整回滚**：若新版已改写配置/记忆/账本且不兼容，成套恢复同一个切换时点的部署快照。若游戏也需回退，服务器存档与玩家数据一起恢复。先告知用户这会丢失该快照之后的聊天记忆、物品/建筑进度；不能自动覆盖新数据。
- 只启动旧版一套，核对家与设施、人格/近期对话、模型模式、进程按钮和观看入口。失败候选与新数据保留，避免反复在同一目录覆盖。
