# 启动器 2.10.3 修复与验收

- Windows 会话内共用一个命名互斥对象，不包含版本号或安装路径。取得它后才创建 Api、托盘和窗口，重复启动在服务控制器创建前退出，因此不会执行停止服务的退出逻辑。已有窗口会尝试显示并置前；首次还在初始化时第二个进程退出，等待首个窗口出现。句柄由内核随进程退出释放，不留下锁文件。
- 新版还能按品牌窗口标题识别已打开的旧版，避免新版加入旧版的服务管理。旧 EXE 本身没有此修复，不能阻止用户继续从旧路径双开旧版；桌面快捷方式已更新到新版。
- 实际守护状态为 `paidSwitches=0`、同文件的废弃 `fallbackSwitches=4`。此前界面读错字段；现在使用 `paidSwitches` 和 `maxPaidSwitchesPerDay`，文案“今日切入备用”仅指自动守护切入备用渠道，不统计免费渠道内部轮换或手动选模。按上海日期跨日显示0；缺失、损坏或未来日期显示统计不可用。配置上限0仍显示0。
- 模型切换区保留原有风格，改为直接选择自动/手动；手动模式自动加载完整模型列表，支持撤销待保存选择、失败重试和键盘焦点，轮询不覆盖草稿。读取列表不生成模型请求。

验证使用真实 Win32 命名对象及隔离测试进程，覆盖并发拒绝、正常释放、进程退出释放和旧窗口拒绝后释放；没有启停真实 Cortico、QQ 或 Minecraft。UI 使用模拟 pywebview API 进行交互测试，在960×660自动模式、860×600手动模式用浏览器渲染检查。它们不能代替真实 WebView2 窗口唤回和用户现场验收。

交付检查：33 项 Python 测试、6 项页面交互测试通过；独立产物的 PE 版本为2.10.3，内含 single_instance / guard_status 模块，打包页面与源码哈希一致；桌面快捷方式已备份并切到新产物。预览和测试均未连接真实模型。

使用已更新的桌面入口。重复打开应只显示原窗口；收进托盘后再次打开应显示同一窗口。正常退出唯一窗口仍会按既有约定停止托管服务。旧版、配置和存档保留，未自动关闭用户已经打开的窗口。
