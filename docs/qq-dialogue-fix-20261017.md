# 2.10.1：QQ 对话与模型入口修复

适用：Cortico 0.2.1、QQ 扩展 `cortico-world-qq-better-alont1` 0.1.17。未修改 Core、人格记忆和 Clash。

## 已核实的原因

- 自问自答样例：17:03 已发出的话，在 17:06 的历史查询里和对方发言共用会话标识；没有新用户发言时模型接着回答自己的问题。历史查询缺乏明确的发送方方向，新版扩展也没有本地实际发送账本。
- 另一处相同正文相隔约三分钟重新调用 `qq_send`，中间有用户新消息。因此不能把所有复述认定为网络重试，也不能无条件禁止新消息后的相同回答。本轮同时改善历史语义，传输去重限定在无新消息及完全相同内容。
- 启动器固定检查 18899，活动模型实际使用 8326，导致入口误报。
- 00:08:07 起 QQ 辅助生成报 `TypeError: fetch failed`。主动说话、情绪感知仍指向旧 18899 和旧模型；活动入口的鉴权模型列表可读，但不含旧辅助模型。这条错误并不能证明 Clash 出口关闭造成故障。QQ 辅助调用与 Core 主模型调用是不同链路。
- 人册旧备注含 DSH 进行时，会作为历史信息随消息和主动上下文注入。新增历史标识，避免当成当前任务；未改写人册原文，重启后是否仍追问需用户验收。

## 安装与范围

`node patches/patch-qq-dialogue.mjs --check` 只预检；`--apply` 安装。版本和锚点不匹配即停止，重复安装不叠加。源码旁的 `.dialogue.orig` 保存首次原文件；新增 `dialogue-ledger.ts` 来自自有 addon，完整发送回执保存在该 World 数据目录的 `qqbot-dialogue.json`，含聊天内容，不得入库。

去重窗口十分钟：同会话、同正文和引用目标、期间没有新入站消息，或同一发送仍进行时，返回“未重复发送”。新消息解除该限制。失败和部分发送保留真实状态，不伪造全部成功；对账本损坏保留原文件并警告，退为内存记录。

`node tools/repair-qq-aux-route.mjs` 只预检；`--apply` 仅修复已启用且仍指向旧本机 18899 的主动说话、情绪感知配置。自定义入口不覆盖。原配置旁保留独立时间戳备份，复用活动渠道的模型及密钥名称，不复制密钥。

辅助入口修正后会恢复原已启用功能的模型调用，仍消耗相应渠道额度；本轮没有增加新后台任务或生成探针。模型列表可读不等于生成与额度已经验证。手动选择不同模型时这两项不会自动跟随，需要单独检查。
