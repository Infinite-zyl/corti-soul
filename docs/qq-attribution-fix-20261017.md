# QQ 归属与重复对话修复：2.12.1

本轮日志可核验的路径：主动调度发送回执被归档为internal的qq.message；历史工具只按qq.message类型取记录，并把事件一律标为对方发言。后续交接因此可能把自己的问句写成用户的问题。主动聊天素材又只有收到的旧话，缺少实际发送回执，容易把自己负责的事项拿来催问用户。

## 修改

- 后续主动发送通知改为qq.sent、internal、meta.self=true，只搭车投递，不独立唤醒。
- 历史和搜索识别旧internal self消息；发送通知与传输账本去重，系统记录不作为收到的用户发言。
- 主动聊天素材包含本会话真实收发方向及实际发送回执；不混入其他私聊。没有新素材或无法确认事项归属时允许输出[skip]，不发送、不计发送配额，等待原有冷却。
- QQ环境语义和Persona交接段说明区分提出者、执行者、状态与证据；自己的问句不转成用户请求，自己的任务不转嫁给用户，未回复的自发消息不自动变成待办。最新取消和完成凭据优先于旧笔记。
- 保留旧记忆与聊天原文，不改写私人笔记。历史修复在读取时生效；已经写入的错误归属需由模型按原始记录核对，不能声称所有重复都已永久解决。

## 安装与回退

在既有QQ对话、路由补丁之后执行`node patches/patch-qq-attribution.mjs --apply`，默认只预检。适配QQ扩展0.1.17，先核验所有锚点再写入，备份为各源文件旁.qq-attribution.orig。重复安装哈希保持一致；重装旧QQ补丁后需最后重装本修复。

停Cortico后，在同一源码版本内恢复本轮备份可回退；恢复前保留后续修改。不要把旧备份直接覆盖未来上游版本。正常重启才加载本次修改；没有真实发送QQ消息、启动bot或调用模型来验收。

## 验证与实际验收

8项收发账本测试、2项补丁预检/重复安装测试、6项实际QQ扩展假传输测试、30项既有交接测试通过。QQ扩展定向兼容类型检查使用Node22支持的ES2023，并关闭扩展原有未用变量诊断；未降低部署配置。

用户重启后验收：

1. 一次正常问答完成后，让她继续游戏，不应因完成事件或交接再答同一个旧问题。
2. 她主动发出的问句应保留为自己的发言，不能在后续交接记成用户请求。
3. 委托她完成一项游戏工作并核验回执，重启后应先核对自己的进度，不能反问用户是否完成了这项工作。
4. 没有新材料时允许安静，不硬找旧事项催问。保留发生时间供后续对照，不能用通过单元测试代替长期实测。
