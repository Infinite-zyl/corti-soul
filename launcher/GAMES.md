# `game_controls.py` / `ui/games.js` — 启动器游戏页

「游戏」与聊天服务的「启动全部」独立。先开启 MC 服务器，在线后再选择观察者或玩家客户端；未配置路径、控制台离线、服务器未就绪均给出状态并禁用相应启动操作。服务器停止走 World 原接口，需二次确认；按 reachable + pid 区分外部服务，不按端口杀进程。配置入口打开 MC World。

`Api.get_games_status()` 返回立即可用的缓存，后台最多每3秒读取 World 状态；游戏页可见时每4秒更新，聊天状态轮询不等待游戏请求。`Api.game_action(game, lane, action)` 接收 `minecraft`、`server/client/player/viewer` 与 `start/stop`，只提交异步操作；同时只允许一个游戏操作。最终状态由接口读回，更新代数防止旧轮询覆盖动作后的新状态。

`ADAPTERS` 预留 `dst`，状态列表稳定包含 `available:false` 的饥荒项。未来接入时提供真实 World 的状态和生命周期适配，沿用同一个操作签名与前端分组；当前不会探测、启动或改动饥荒文件。

手机观看独立于 World。启动器使用仓库 `launcher/.venv` 和已安装观看组件；路径从当前仓库根解析。Windows 虚拟环境 Python 会有中转进程，因此用本次随机运行标识核对本机状态，用 `ChildJob` 绑定实际创建的进程树，避免按端口或中转 PID 猜归属。退出时关闭本启动器新建的观看，复用的外部观看保持运行；手机主动关闭后状态自动回读。原来的两个 CMD 入口继续可用。

界面保持现有紫色风格；切到游戏时收起聊天配置区，切回恢复。按钮节点在轮询间保留；操作中禁用重复点击，错误保留到后续操作。最小窗口允许内容滚动，不把底部提示压在按钮上。资源由 `ui_assets.load_ui` 内联进 pywebview 的 HTML，同时适用于源码与冻结 EXE。

验证：Python 启动器测试18项、桌面 DOM测试5项、观看服务测试15项通过。已用真实本机 World 的只读状态接口核对，用手机尺寸 Edge 接收真实观察者画面并验证取消和确认关闭，关闭后 MC 服务器与观察者仍在线。未用启动按钮启停真实游戏或 bot；未把桌面模拟状态截图或手机尺寸浏览器当作原生窗口/实体手机验收。
